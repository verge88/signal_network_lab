# Проверка достоверности · приложение 2.10, движок 2.5.1

Откройте **Исследование → Проверка достоверности…** или **Эксперименты → Проверка достоверности модели → Открыть сравнение**. Модуль сравнивает измерения с фиксированной конфигурацией, не подбирает параметры и не меняет проект. Отчёты сохраняют снимки конфигурации, плана допусков и SHA-256 входного CSV. Изменение настроек не переписывает старые проверки.

## Порядок работы

1. Настройте топологию, процедуры, длительность и окно как на измеренном стенде. Если нужна калибровка, выполните её заранее и примените результат.
2. До сравнения откройте **Допуски и условия**. Задайте ошибки, обязательные метрики, минимальное число независимых опытов и задержек, число seed. Добавьте нагрузки и сценарии, отсутствие которых должно попасть в отчёт.
3. Сохраните **Шаблон CSV** и заполните измерениями. Для знакомства используйте **Синтетический пример**: он явно помечен `synthetic` и не подтверждает внешнюю достоверность. Кнопка **Сохранить измерения…** сохраняет заполненный пример или загруженный файл.
4. Нажмите **Загрузить измерения**, затем **Сравнить**. Расчёт выполняется в фоне и поддерживает основную кнопку отмены.
5. В **Сравнении** выберите опыт и метрику. Сверху — наложенные распределения задержек, снизу — временные ряды. Измерения обозначены сплошной линией, симулятор — штриховой; различие сохраняется в монохроме.
6. **Отклонения** показывает агрегатные ошибки всех опытов и оконные ошибки выбранного опыта/метрики. **Условия проверки** разделяет нагрузки, сценарии и конфигурации, включая запрошенные, но отсутствующие условия.
7. Сохраните **HTML** с векторными графиками или **JSON** с отдельными seed и ошибками каждого окна. **Экспорт графиков и таблиц…** поддерживает обычные стили и форматы приложения. Проверки сохраняются в истории этого окна.

## Формат измерений

Одна CSV-строка — один опыт при одной нагрузке и сценарии. UTF-8, разделитель запятая, десятичная точка. JSON заключайте в CSV-кавычки с удвоением внутренних кавычек. Синтетический пример создаёт корректный заполненный файл.

| Поле | Значение |
| --- | --- |
| run_id | Идентификатор опыта, до 100 символов |
| offered_rate | Суммарная интенсивность новых базовых процедур, msg/s, `(0,3000]`; потоки масштабируются пропорционально |
| delivery_ratio | Успешные процедуры / все процедуры, от 0 до 1, не проценты |
| latency_mean / latency_p95 / latency_p99 | Задержка успешной процедуры от создания до последнего успешного ответа, ms |
| throughput | Успешные завершения в интервале наблюдения / длительность, 1/s; хвост не входит |
| retry_ratio | Повторы DATA / попытки DATA транспорта; ACK исключены, как в калибровке |
| recovery_ms | Среднее время до первого успешного завершения после физического конца каждого события, ms, как в калибровке |
| latency_samples_ms | 20–20 000 задержек успешных процедур через вертикальную черту |
| scenario | Подпись условия, по умолчанию `project`. Сама не меняет события |
| incidents_json | Массив событий. `[]` отключает события и атаки проекта; пустое поле сохраняет их. Явный массив выключает атаки проекта, чтобы не наложить их повторно |
| source_kind | `synthetic`, `lab`, `unknown`; отсутствие означает `unknown` |
| measurement_id / device / firmware / measured_at / raw_sha256 | Для `lab` обязательны. Время ISO 8601 с часовым поясом; SHA-256 исходного файла — 64 шестнадцатеричных символа |
| duration_s / window_s | Необязательно: длительность 10–600 целых секунд и окно 1–30 целых секунд; иначе берутся из проекта |
| evaluation_role | `validation` — заявлена независимая проверка; `calibration` — данные подбора; `unknown` или пусто — независимость не заявлена |
| time_series_json | Массив окон с `time`, `width_s` и измеренными метриками, например `[{"time":0,"width_s":5,"latency_p95":42,"delivery_ratio":0.99,"throughput":19}]` |

Нужны run_id, offered_rate и хотя бы одна агрегатная метрика. Ограничения: 5 МБ, 100 опытов, 1200 точек времени на строку, оценочный бюджет 2 млн базовых процедур с учётом seed.

Сопоставляются только одинаковые начала и ширины окон, без интерполяции. Последнее окно может быть короче. Полнота требует всех окон `[0,duration)` и обязательных метрик в каждом из них. Оконный throughput — завершения в окне / его ширина. Задержки относятся к процедурам, созданным в окне, как в телеметрии. Если успешных процедур нет, симуляционная задержка считается отсутствующей, а не нулевой. Оконные retry_ratio/recovery_ms движок отдельно не выдаёт; их требование для полного временного ряда даст недостаточность данных.

## Допуски и выводы

Абсолютная ошибка — `|симулятор − измерение|`. Разрешённая ошибка — `max(абсолютный допуск, относительный допуск × |измерение|)`. Например, при p95 = 80 ms и настройках 5 ms / 10% разрешено 8 ms. При измеренном нуле относительная ошибка не определяется, применяется абсолютный допуск.

| Метрика | Абсолютный допуск по умолчанию | Относительный |
| --- | --- | --- |
| Успешность | 0.01, один процентный пункт | 0% |
| Средняя задержка | 2 ms | 10% |
| p95 | 5 ms | 10% |
| p99 | 10 ms | 15% |
| Завершения | 1 /s | 5% |
| Доля повторов | 0.01 | 0% |
| Восстановление | 25 ms | 15% |

Это исходные настройки программы, а не нормативы конкретного оборудования. По умолчанию обязательны успешность, p95, throughput, распределение и полный ряд; требуются три независимых опыта, три seed на опыт, 50 задержек с каждой стороны. Можно задать 1–10 seed и 2–20 опытов. Все предоставленные метрики проверяются; галочка обязательности дополнительно требует наличия метрики.

Предсказания агрегатов и окон усредняются по seed; отдельные агрегаты seed сохранены в JSON. Ошибки не усредняются между независимыми опытами: один выход за допуск даёт «Вне допуска» всему условию. При нехватке опытов, обязательных полей или сопоставимых окон появляется «Недостаточно данных». Отчёт содержит причины; при одновременно найденной ошибке и нехватке данных сохраняется статус «Вне допуска» с перечнем недостающего.

ECDF — доля задержек не больше X. KS-расстояние — максимальный разрыв двух ECDF; одномерное Wasserstein-расстояние измеряется в ms. Исходные границы 0.15 и 5 ms. Это расстояния без p-value или заявления статистической эквивалентности. Отображается до 400 различных X; расстояния считают по всей выборке. Симуляционные задержки берутся из равномерного журнала успешных завершённых процедур: trace_limit влияет на полноту распределения, но не на точные агрегаты. Определения: [KS в SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.ks_2samp.html), [Wasserstein в SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.wasserstein_distance.html).

## Независимость и область применимости

Независимыми считаются только строки `evaluation_role=validation`. Совпадения с любой сохранённой калибровкой исключаются по группе и SHA-256 исходного файла. Строки одного опыта или файла объединяются транзитивно в одну группу. Переименование run_id или разбиение того же опыта на файлы не увеличивает число независимых опытов. Общий файл считается одной группой консервативно, даже при разных measurement_id. Исходные идентификаторы, файлы и независимость всё равно заявлены исследователем.

Условия разделяются по сценарию, нагрузке и конфигурации: событиям, длительности, окну и профилю потоков. Одинаковое название при разных событиях не объединяет результаты. Ожидаемое условие без измерений получает недостаточность данных. «В допуске» для синтетики подтверждает только внутреннее сравнение; `lab` обозначает заявленные измерения стенда, подлинность артефактов автоматически не проверяется. Аппаратная достоверность не объявляется доказанной.

Выводы не распространяются на отсутствующие нагрузки, отказы, топологии, версии оборудования или длительности. Реальные измерения оборудования не приложены; пример и тесты проверяют механизм сравнения.

## Исправление перекрывающихся отказов

В движке 2.5.1 восстановление не публикуется, пока на том же узле или направлении канала остаётся другой физический отказ или наблюдаемый период восстановления. Для `[2,5)` и `[3,7)` нет UP в 5 секунд; с нулевой задержкой восстановления он появляется в 7. Задержки наблюдения и распространения сохраняются. Версии соответствуют времени наблюдения, поэтому старое событие с более поздним восстановлением получает актуальную версию. Журнал отличает конец одного события от восстановления всего ресурса.
