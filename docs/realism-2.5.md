# Достоверность модели — движок 2.5, приложение 2.8

Версия расширяет ресурсы хранения, пользовательский сервис и выбранные управляющие состояния. Она не доказывает совпадение с оборудованием и не является реализацией полных протокольных стеков. Всё выполняется внутри дискретно-событийной модели.

## БД и кэш

Редактор узла → **БД, кэш и контексты**. По умолчанию используется `storage_model=queued`:

- CPU освобождает обработчик перед ожиданием БД. У БД отдельные `db_connections`, очередь `db_queue_limit` и общий срок ожидания/выполнения `db_timeout_ms`. Задержка операции — `database_ms`; она не включается в занятость CPU.
- Переполнение даёт `database_queue_overflow`, превышение срока — `database_timeout`. Таймер имеет приоритет при совпадении времён.
- Кэш данных использует LRU и TTL: `cache_entries`, `cache_ttl_s`. Ключ: узел, исходная группа UE, абонент, операция. Размер 0 отключает кэш; начальное состояние холодное. Попадания определяются предыдущими обращениями.
- Ответы для повторных транзакций хранятся отдельно: `transaction_cache_limit`, `transaction_cache_ttl_s`. Сохранённый ответ исключает повторный запрос БД. Одновременные промахи ещё не завершённых транзакций могут порождать несколько операций БД.
- Перезапуск очищает кэш и контексты, отменяет ожидающую работу; позднее завершение прежней эпохи не создаёт состояние заново. Временный отказ прекращает работу, но сам по себе не очищает кэш.

Старое приближение доступно через `storage_model=probabilistic`: вероятность `cache_hit_ratio` и добавка `database_ms` к CPU. В queued параметр cache_hit_ratio не действует. СУБД, SQL, дисковый I/O, изоляция транзакций и репликация не реализованы: моделируется ограниченный сервис доступа к данным.

## Контексты и окончание PDU

`context_limit` ограничивает количество записей на узел; `context_ttl_s` задаёт TTL. Живой контекст не вытесняется ради нового: возвращается `context_limit`. Истечение освобождает место, запись состояния продлевает TTL; старый таймер не удаляет обновлённую запись.

Начальная регистрация 5G задаётся когортой в начале опыта и материализуется при обращении. Её нельзя заново получить после перезапуска или истечения уже созданной записи. Лимит применяется при материализации, а не через предварительное выделение всех записей миллиона абонентов.

В потоке `session_lifetime_s` задаёт локальное окончание PDU после успешной установки. Значение 0 оставляет только TTL. Освобождаются принадлежащие сессии флаги AMF, SMF, UPF и PCF; старый таймер не удаляет заменившую её сессию. Поздние запланированные пакеты фиксируют потерю контекста. Освобождение локальное: полный NAS/PFCP обмен удаления и deregistration не реализованы.

Регистрация перепроверяется при завершении PDU: истёкшая во время внутренних RPC запись не должна превращаться в успешную сессию. В версии 2.5 модель представляла одну связность без отдельных PDU Session ID. Начиная с 2.13 это ограничение снято: см. [жизненный цикл сессий](session-lifecycle.md), включая модельный обмен освобождения, отмену регистрации и согласование оставшихся ресурсов.

## Приложения и QoS

В редакторе потока **5G · Пользовательский трафик** доступны четыре профиля:

| Профиль | Отправки |
| --- | --- |
| Равномерные проверки | Заданный интервал |
| Интерактивный | Экспоненциальные интервалы с заданным средним и отдельным воспроизводимым генератором |
| Видео | Заданный интервал в фазах активности, затем пауза |
| Передача файла | Интервал в десять раз меньше заданного, при прежнем количестве пакетов |

Профиль не превышает `data_packets`; размер задаётся `data_bytes`. `data_priority` влияет на очередь CPU, без прерывания обработки; каналы сохраняют FIFO. `qos_budget_ms` оценивает RTT: доставленный позднее бюджета пакет остаётся доставленным, но не удовлетворяет QoS. При бюджете 0 любой доставленный пакет проходит эту проверку. Это независимо от `data_timeout_ms`.

Это профили датаграммной нагрузки, а не HTTP, TCP/QUIC, видеокодек или измерение качества просмотра.

## Правила UPF

Редактор UPF → **5G · Правила UPF → Настроить**. Правила выбирают поток, DNN, S-NSSAI и направление; пустой селектор означает любое значение. Меньший precedence проверяется раньше, при равенстве важен порядок. Используется первое совпадение: пересылка или отбрасывание, ограничение скорости, бюджет всплеска, максимальный пакет.

При отсутствии совпадения используются действие и скорость UPF по умолчанию. Скорость 0 означает отсутствие ограничения в выбранном правиле/настройке. Token bucket имеет конечную FIFO-очередь `upf_queue_limit`; переполнение даёт `qos_queue_overflow`. Пакет больше бюджета всплеска отклоняется (`qos_burst_exceeded`). Направления имеют отдельные бюджеты, совместно используемые сессиями одного правила. Последующие передачи потребляют обычные ресурсы пути; тайм-ауты и потери по-прежнему возможны.

Трасса содержит выбранные правила, сводка — очереди, ожидание и причины отбрасывания. Это функциональные аналоги выбранных действий распознавания, пересылки и QoS. Бинарных PFCP IE, TEID, полных PDR/FAR/QER, 5QI/GBR и радиопланировщика нет.

## Мобильность

Готовый пример: **Вид → Шаблоны топологии → 5G · мобильность и QoS**. Он содержит вторые gNB, AMF и UPF с нужными каналами. Собственное расписание: редактор потока → **5G · Мобильность → Настроить**. Задаются время, новые узлы, минимальная пауза, тайм-аут и перенос контекстов.

Перемещение относится к общей когорте потоков с одинаковыми исходными gNB, AMF, PLMN, S-NSSAI и DNN. Одновременные переносы той же когорты не выполняются параллельно. Число абонентов и состав когорты должны соответствовать гипотезе опыта.

Перед переключением проходят NGAP-запрос с нового gNB, при смене AMF — запрос переноса по SBI, при смене UPF — запрос переноса сессии по PFCP. Каждый требует ответа и использует обработчики, очереди, полосу, потери и транспорт модели. Это выбранные поведенческие обмены с обобщёнными именами, не все последовательности handover 3GPP.

Контексты перемещаются после ответов и минимальной паузы, с проверкой доступности, профиля AMF, лимита и конфликтов контекстов. Недоставленный ответ даёт `handover_timeout`; прежнее размещение сохраняется. При отключённом переносе новые PDU требуют регистрации. Отсутствующие N3/N6 нужно создать отдельно: событие не создаёт каналов.

В паузе данные когорты могут теряться; пакеты прежней эпохи не считаются успешно перенесёнными. Незавершённые сигнальные процедуры прерываются с `mobility_relocation`, новые используют новое размещение. Это консервативное правило, не бесшовный handover. Радио, измерения RRC, индивидуальные траектории UE и буферная переадресация не реализованы.

## Дополнительные управляющие состояния

Diameter CER/CEA проверяет пересечение Application IDs; relay capability 4294967295 допускает соединение без прямого пересечения. Без совместимости — REJECTED и `no_common_application`.

M3UA проверяет необязательный `peer_routing_context` в ASPAC; несовпадение даёт REJECTED и `routing_context_mismatch`. В редакторе канала **Штатное закрытие** запускает DPR/DPA для Diameter либо ASPIA/ASPIA_ACK → ASPDN/ASPDN_ACK для M3UA. После CLOSING → CLOSED новых данных и автоматического открытия нет; ответы прежней эпохи не открывают ассоциацию.

Это дополнительные выбранные состояния. Полные peer election, AVP/Result-Code, ASP/AS, SCTP, SS7 management не реализованы; `ROUTE_UPDATE` остаётся обобщённым распространением доступности. Проверка совместимости настоящих стеков требует отдельного протокольного стенда.

Терминология обменов: [RFC 4666](https://www.rfc-editor.org/rfc/rfc4666.html), [RFC 6733](https://www.rfc-editor.org/rfc/rfc6733.html). Ссылки не являются заявлением о полном соответствии этим стандартам.

## Измерения и переход

Новый CSV и поля происхождения описаны в [методике](calibration.md). Источники различаются как synthetic, unknown и заявленные lab. Сохраняются идентификатор опыта, оборудование, версия ПО, время с часовым поясом, SHA-256 исходных данных и загруженного CSV. Разбиение — по независимому измерению: копии с новыми run_id не становятся независимыми опытами.

Реальные исходные файлы оборудования не предоставлены и не проверены. Метаданные lab — заявление исследователя. Отчёт показывает `raw_artifacts_verified=false` и `hardware_accuracy_proven=false`; снижение ошибки на test описывает только предоставленные данные. Синтетическая регрессия проверяет программу, а не оборудование.

**Телеметрия → БД и контексты** показывает БД, попадания/промахи, очередь/соединения, тайм-ауты, отказы и записи. **5G · мобильность** — результат каждого переноса. Таблицы экспортируются с оформлением; JSON содержит ожидания, вытеснения, истечения, правила и QoS.

Старые файлы получают новые значения по умолчанию. Сохранённые результаты не пересчитываются; новые могут отличаться при прежнем seed из-за реального кэша и БД. Для сравнения старого обслуживания выберите probabilistic. Десять входных признаков ML не изменены, что не доказывает переносимость старого детектора: проверьте его на новых выборках.
