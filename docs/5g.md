# Сигнальная сеть 5G SA — версия 2.3

Откройте **Вид → Шаблоны топологии → 5G SA / Service-Based Core**, затем нажмите F5. Шаблон содержит 12 элементов и три потока: регистрацию, отдельную PDU-сессию и регистрацию с последующим созданием PDU-сессии. Интенсивность задаёт новые процедуры/с; RPC, управление, ответы, повторы и пользовательские тесты добавляют нагрузку автоматически.

## Функции и интерфейсы

| Элемент | Роль в модели |
|---|---|
| gNB | Группы виртуальных UE, выбранные NAS/N2 процедуры |
| AMF | Регистрация и оркестрация доступа, регистрационный контекст |
| AUSF | Аутентификационная процедура с обращением к UDM |
| UDM / UDR | Запросы данных и обновление регистрации |
| NRF | Выбор экземпляров NF по профилю и сервису |
| NSSF | Проверка выбора сетевого среза |
| SMF | Создание и обновление SM context, оркестрация PDU |
| PCF | Решение по политике с обращением к UDR |
| UPF | Контекст N4 и пересылка проверочных пакетов N3/N6 |
| DN | Сеть данных, ответ на пользовательский тест |
| SCP5G | Прокси SBA с ограниченными обработчиками и очередями |

Разделены **NGAP** (gNB–AMF, N2), **SBI** (сервисные вызовы), **PFCP** (SMF–UPF, N4), **GTPU** (gNB–UPF, N3) и **IP** (UPF–DN, N6). Маршрут не перескакивает между доменами. Для управления внутренний ретранслятор — SCP5G. Пользовательский тест последовательно проходит отдельные участки N3/N6 в обе стороны через выбранный UPF.

## Выбранные последовательности

Регистрация: запрос gNB–AMF; discovery AUSF; Nausf с вложенными discovery UDM и запросами Nudm/Nudr; свёрнутый обмен Authentication/Security; опциональный NSSF; UECM registration и SDM get с доступом к UDR. Registration Accept возвращается после успеха зависимостей.

PDU: запрос gNB–AMF; discovery SMF; CreateSMContext с UDM/UDR, опциональным PCF/UDR и PFCP Session Establishment; настройка ресурса на gNB; UpdateSMContext с PFCP Session Modification; итоговый ответ. Это упрощённые последовательности, без полного графа условных ветвей 3GPP.

В комбинированном потоке PDU начинается после получения Registration Accept. Для отдельного PDU настройка **«UE уже зарегистрирован»** задаёт состояние группы UE на начало опыта. Оно материализуется при обращении, без предварительного выделения словаря для каждого из миллиона возможных абонентов. Перезапуск AMF удаляет как созданные контексты, так и право материализовать начальное состояние всей группы: следующий PDU получает `not_registered`. Восстановление требует успешной процедуры регистрации. Обычный `node_down` сохраняет состояние. Регистрационный контекст привязан к AMF, группе gNB, абоненту и настройкам PLMN/среза/DNN; пересекающиеся группы потоков используют общий контекст.

Каждый вложенный RPC и ответ занимают очереди исходного/конечного узла, прокси и каналы. Есть идентификаторы RPC, таймеры, повторы и распространение ошибки к внешнему запросу. `timeout_ms` — внешний таймер, `service_timeout_ms` — внутренний. Дубликат в процессе исполнения не запускает второй экземпляр серверного workflow. Поздние сообщения расходуют ресурсы, но не возобновляют завершённую клиентскую процедуру.

## Настройки и исследование

В расширенных параметрах узла, **5G · Профиль NF**, доступны PLMN, S-NSSAI, DNN, REGISTERED/SUSPENDED и сервисы. Пустой список сервисов означает набор по типу NF; для удаления сервиса задайте непустой список без него. Endpoint NF служит ключом таблицы маршрутизации; при пустом host используется тип NF.

В редакторе потока, **5G · Сервисы и срез**, доступны PLMN, S-NSSAI, DNN, NRF/NSSF/PCF, начальная регистрация, внутренний таймер и привязки вида `{"SMF":"smf","UPF":"upf"}`. При выборе операции 5G автоматически включается NGAP. Старый движок отдельных сообщений для 5G не поддерживается.

NRF выбирает REGISTERED-экземпляр с нужным сервисом, PLMN и срезом; для SMF/PCF/UPF также проверяется DNN. Доступность учитывается с задержкой обнаружения. Loadshare распределяет выбор по абонентам, иначе используется порядок ID. Найденные через discovery NF закрепляются на время процедуры. Без NRF используется локальный выбор по профилям. Отдельного динамического реестра/TTL-кэша нет.

Попробуйте перегрузить SCP5G, отключить UDR, задержать N4, добавить второй AUSF или сменить DNN. Ошибка зависимости прерывает последующие этапы. Перезапуск NF очищает контексты и кэш ответов; старые дочерние вызовы не продолжают новый workflow. Потеря SMF/UPF-контекста проверяется при Update/Modification.

В **Телеметрии → 5G · NF / сервисы** показаны запросы, успехи, ошибки и тайм-ауты. В **Запросах и ответах** — интерфейсы и transaction ID. **5G · N3 / N6** показывает доставку пользовательских тестов независимо от успеха PDU, RTT, goodput и причины неуспехов. Редактор потока задаёт DN, число, интервал, размер и таймер пакетов. JSON содержит профили NF, контексты, выбранные экземпляры и отдельный `user_plane`. [Подробные определения 2.3](realism-2.3.md).

ML-датасеты, групповое разбиение, обучение, inference и калибровка используют общий механизм процедур с определениями признаков `procedures-v2`. Перенос детектора между поколениями сетей требует отдельной оценки. `retry_ratio` калибровки относится к повторам DATA транспорта; PFCP-повторы относятся к RPC и учитываются в счётчиках процедур.

## Границы достоверности

Модель локальная: **выбранные процедуры 5G SA и проверочные пользовательские пакеты**, без внешних соединений. NGAP использует общий надёжный транспорт симулятора. SBI приближённо представляет стоимость RPC и надёжной передачи, без реального HTTP/2, TLS, HPACK и межпоточного TCP HOL. PFCP, GTPU и IP — датаграммы без транспортных ACK/повторов; восстановление PFCP выполняет таймер RPC, а пользовательский тест ограничен отдельным таймером.

Полные автоматы и кодирование NAS/NGAP/PFCP/GTP-U, настоящие SCTP/TCP/UDP сокеты, 5G-AKA и криптография, радиоканал/RRC, mobility/handover, roaming, NSA и N26 interworking не реализованы. Пользовательский тест проверяет поведенческую пересылку с общими ресурсами, без реальных TEID/PDR/QER, IP-стека и NAT. Успех управления и успех данных остаются разными показателями. Профили NF заданы конфигурацией, без полного NF registration/heartbeat.

Архитектурные ориентиры: [3GPP TS 23.501 / ETSI TS 123 501](https://www.etsi.org/deliver/etsi_TS/123500_123599/123501/18.05.00_60/ts_123501v180500p.pdf) и [TS 23.502, разделы 4.2.2 и 4.3.2](https://www.etsi.org/deliver/etsi_ts/123500_123599/123502/18.11.00_60/ts_123502v181100p.pdf). Соответствие стандарту и совпадение с оборудованием не заявляются; для последнего нужны независимые измерения и калибровка.
