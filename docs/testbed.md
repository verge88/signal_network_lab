# 5G-стенд на WSL2

**Исследование → 5G-стенд…** управляет отдельно установленными Open5GS и UERANSIM внутри выбранного Linux-дистрибутива WSL2. Это реальные процессы, протокольные обмены и время выполнения. Симулятор SignalLab остаётся самостоятельным режимом с модельным временем, seed и контрольными точками. Произвольный граф топологии не преобразуется в развёртывание: первая версия предоставляет один шаблон 5G SA, один gNB, один IPv4 DNN/срез и до 16 тестовых UE.

## Проверенная среда и предварительные требования

Проверен полный цикл в Ubuntu WSL2 с ядром `6.18.54.1-microsoft-standard-WSL2`, Open5GS `2.8.0~noble5` и установленными UERANSIM-бинарными файлами. Сохранён SHA-256 `nr-ue`, потому что номер исходного тега не всегда доступен. Проверка фактически создала SCTP-сокет, зарегистрировала UE, установила PDU и получила 5/5 ICMP-ответов через UE TUN до локального UPF-шлюза. Это проверка конкретной среды, а не обещание совместимости любого WSL-ядра или точности модели реального оборудования.

Нужны Python 3, PyYAML, iproute2, ping, Open5GS с исходными YAML-конфигурациями, UERANSIM `nr-gnb`, `nr-ue`, `nr-cli`, доступная локальная MongoDB на `127.0.0.1:27017` и PyMongo либо `mongosh`. Текущий адаптер не настраивает аутентифицированную или внешнюю MongoDB. База тестовых абонентов отдельная, с именем `signal_lab_<ID профиля>`.

Проверка **Linux-среда → Проверить среду** показывает каждую зависимость, доступность SCTP и `/dev/net/tun`, права и форму конфигураций `sbi.server`/`pfcp.server`. Если SCTP отсутствует, запуск следует отложить до подготовки подходящего WSL-ядра; приложение не обновляет ядро и не меняет `.wslconfig`. Старое предупреждение о WSL в документации UERANSIM нельзя заменять предположением о совместимости: ориентируйтесь на фактические проверки своей среды.

Компоненты устанавливаются отдельно по официальным руководствам. SignalLab не скачивает и не устанавливает их автоматически, не содержит их бинарные файлы и не перезапускает системные службы. Совместимость конфигураций проверяется до запуска.

## Первый запуск из интерфейса

1. Нажмите **Найти дистрибутивы** и укажите имя WSL2-дистрибутива, например `Ubuntu`. Служебный `docker-desktop` для этого шаблона не используется.
2. Для создания сетевого пространства, интерфейсов, UE и UPF включите **Выполнять операции стенда от root внутри выбранного WSL-дистрибутива**. Это не повышение прав Windows-приложения. Команды направляются через `wsl.exe --distribution … --user root --exec python3 …`; пароль в SignalLab не вводится.
3. Укажите каталоги Open5GS, его конфигураций и UERANSIM. **Проверить среду** ищет также стандартные расположения UERANSIM в `/opt` и домашних каталогах. При найденном подходящем пути нажмите **Использовать найденный путь** и повторите проверку.
4. На вкладке **Конфигурация SA** задайте MCC/MNC, TAC, SST/SD, DNN и подсети. Значения согласуются с gNB, UE, AMF, NRF, SMF, UPF, NSSF и абонентскими профилями. RAN использует частную IPv4-сеть /30. Для UE выбирайте непересекающуюся частную /16…/28; начальное значение — `10.84.0.0/24`. При существующем ogstun с `10.45.0.0/16` использование той же подсети новым стендом будет отклонено.
5. На вкладке **Тестовые абоненты** добавьте IMSI, K и OPc. IMSI должен начинаться с MCC/MNC профиля; строки должны быть уникальны. Начальные ключи случайные и предназначены только для собственного тестового стенда. Их поля скрыты по умолчанию. В локальной библиотеке профиль сохраняется с ключами без шифрования; рабочие SIM-ключи здесь не используйте.
6. Сохраните профиль. На вкладке **Запуск и диагностика** нажмите **1 · Подготовить**. Программа клонирует установленные конфигурации в собственный каталог `/var/tmp/signal-lab-<ID>`, согласует адреса и создаст сеть профиля. Исходные `/etc/open5gs` не перезаписываются. Размер каталога и файлов ограничен текущими настройками; права каталога 0700, конфигураций 0600.
7. Нажмите **Записать абонентов в стенд**. Изменяются только записи этого профиля в его отдельной MongoDB-базе. Применение абонентов не удаляет все существующие записи. Для удаления конкретного тестового IMSI есть отдельная кнопка.
8. Нажмите **2 · Ядро**. Компоненты запускаются по порядку. Проверяется процесс и открытие SBI; перед завершением запуска также ожидается подтверждение PFCP SMF↔UPF. Наличие процесса UPF само по себе не равно успешной PDU-сессии.
9. Нажмите **3 · gNB**, затем **4 · UE**. Кнопка **Обновить** получает реальные статусы через `nr-cli status` и `ps-list`. Процесс gNB, регистрация UE и активная PDU показаны отдельно. Если UE ещё не зарегистрирован, обновите состояние и изучите журналы; мгновенный запуск процесса не объявляется регистрацией.
10. На вкладке **Измерения и сравнение** нажмите **Измерить и сохранить**. Для каждой активной IPv4 PDU-сессии программа сопоставит адрес с реально существующим `uesimtunN` и выполнит пять ICMP-проб до локального шлюза UPF. Неоднозначный или отсутствующий TUN даёт ошибку, а не тест через другой интерфейс.

## Изоляция и жизненный цикл

gNB и UE запускаются в собственном Linux network namespace `slran-<ID>`. С ядром его соединяет собственная veth-пара; UPF получает отдельный TUN. Это позволяет использовать одну WSL2-среду с разделением сетевого стека RAN и core. Для SBI ядра используется отдельный диапазон loopback `127.20.0.x`. Одновременно два профиля с теми же адресами ядра не запускаются: занятые адреса отклоняются при подготовке.

Приложение не меняет системный NAT, глобальный forwarding, Windows Firewall, маршруты Windows, пакетные репозитории и чужие сетевые службы. Поэтому начальный тест подтверждает прохождение данных до локального UPF-шлюза. Интернет, внешняя N6-сеть и производительность приложений требуют отдельного плана и подготовки маршрутизации; пять успешных ping их не подтверждают.

**Остановить** посылает сигнал только процессам из сохранённого манифеста с совпадающими PID, временем рождения, исполняемым файлом и собственным конфигурационным путём. Чужие Open5GS/UERANSIM-процессы по общему имени не завершаются. **Очистить сеть** удаляет только namespace и интерфейсы профиля после остановки процессов. Журналы, конфигурации и база абонентов остаются для проверки. При частичной подготовке очистите её сеть, затем подготовьте заново.

Перед изменением подготовленных сетевых параметров или списка UE остановите процессы, очистите сеть и повторите подготовку. Имя профиля можно менять отдельно. Профиль связан с ID, поэтому выбор другого профиля не даёт права завершать процессы первого.

Операции выполняются в фоновых заданиях. **Отменить ожидание** прекращает ожидание Windows-клиента; это не транзакционный откат Linux и не обещание остановки уже запущенных процессов. После отмены или обрыва связи нажмите **Обновить** и при необходимости **Остановить**. Локальная блокировка состояния предотвращает одновременную мутацию одного профиля.

## Что именно измеряется

Отчёты сохраняются отдельно от симуляций: `source=open5gs-ueransim`, `clock=wall`, UTC-время опроса, версия Linux/Python, пакет Open5GS, отпечаток UE-бинарного файла, параметры и контекст сети. Тестовые ключи в отчётах скрываются. На экране и в истории не используется seed как доказательство повторяемости реального запуска.

**ICMP**: сохраняются передано/принято, отдельные RTT, среднее и p95. p95 здесь — ближайшая сверху порядковая статистика `ceil(0,95·n)`; при пяти ответах это максимум. Это малая диагностическая выборка, не оценка SLA. Отсутствующий ответ или недоступные измерения не превращаются в нулевую задержку. График отображает до восьми UE, таблица и JSON содержат все.

**Процедуры NAS**: адаптер `ueransim-nas-paired-v1` сопоставляет строки одного UE о передаче Initial Registration или PDU Session Establishment Request с соответствующей успешной обработкой либо отказом. Время — часы Linux из журнала, точность исходных отметок 1 ms. Отказы сохраняются отдельными событиями. Незавершённые, неоднозначные и отрицательные по времени пары не получают длительности. Счётчики сбрасываются по смещению начала текущего процесса, чтобы повторный запуск не присваивал себе старые события. Журнал больше 1 МБ не анализируется этим адаптером и отмечается как недоступный.

Это границы NAS send→success/reject в UERANSIM, а не аппаратные измерения конкретного узла. Другие версии текстовых сообщений могут потребовать нового адаптера. Полные доступные пары, неполнота и имя адаптера сохраняются в JSON. Переход через полночь обработан; часы разных компьютеров не сопоставляются.

Вкладка **Измерения и сравнение** позволяет открыть результат симуляции рядом со стендом. Она не считает ошибку между ICMP RTT и задержкой регистрации и не подаёт их автоматически в калибровку. Для действительной проверки нужны совпадающие границы процедур, наборы независимых опытов, нагрузки, допуски и достаточно наблюдений. Согласованные измерения можно затем подготовить для существующей **Проверки достоверности**. Успех запуска программного стенда не доказывает совпадение симулятора с оборудованием оператора.

## Сохранение и экспорт

Профили хранятся в библиотеке окна, измерения — в отдельной истории. **Отчёт JSON** сохраняет полный результат с происхождением. Через обычный **Экспорт…** доступны таблицы UE/PDU, ICMP, парных NAS-событий и график RTT, с настройкой оформления и штатными форматами.

**Экспорт конфигураций** создаёт ZIP с UE/gNB-конфигурациями и профилем, включая тестовые K/OPc. Предпросмотр на экране скрывает их. Core-конфигурации формируются на Linux из реально установленной версии и сохраняются в каталоге стенда; экспорт ZIP не выдаётся за готовый core для произвольной версии Open5GS.
