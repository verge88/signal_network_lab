# Пошаговый разбор · приложение 2.11, движок 2.6

Откройте **Телеметрия → Транзакции**, выберите строку и нажмите **Разобрать процедуру**. Двойной щелчок по строке делает то же самое. Другой вход — **Исследование → Пошаговый разбор процедуры…**. Разбор относится к выбранному сохранённому прогону, даже если текущая топология уже изменена.

## Запись и выбор сессии

В **Экспериментах** задаются **Подробных сессий** и **Событий на сессию**. По умолчанию записывается подробная выборка из 20 процедур, до 2000 событий в каждой. Разрешены 0–100 сессий и 100–10 000 событий; 0 отключает автоматическую запись. Нажмите **Применить**, затем выполните прогон.

Выборка подробных журналов равномерна по начавшимся процедурам и использует отдельный генератор случайных чисел. Отбор делается при создании процедуры: выбранная сессия записывается с самого начала. По ходу прогона часть ранних сессий может быть вытеснена из выборки. В итоговый журнал входят сохранившиеся сессии. Основная выборка завершённых транзакций существует отдельно; их состав не обязан совпадать. Журналирование не меняет модельные времена, генерацию нагрузки и результаты доставки, но требует дополнительного времени и памяти на самом компьютере.

Список **Сессия** содержит ID процедуры, внутренний идентификатор сессии, операцию, итог и отметку наличия подробностей. Внутренний ID абонента — индекс модельной группы UE, а не настоящий IMSI.

Если журнал отсутствует, нажмите **Записать выбранную процедуру**. Программа полностью повторит исходную конфигурацию и seed, записав выбранный ID с лимитом 10 000 событий. Результат сохраняется отдельным прогоном; исходный прогон и текущая конфигурация рабочего проекта не перезаписываются. Метрики и временные окна сравниваются с оригиналом. При другой версии движка результат может отличаться; равенство агрегатов само по себе не является доказательством идентичности старой сессии. Журнал старого запуска не восстанавливается из агрегатов.

При достижении лимита окно явно показывает число пропущенных событий. Итог процедуры сохраняется, но отсутствие записи после обрезания не означает отсутствия события. Состояние после последней записанной строки неизвестно.

## Навигация

- **В начало / Назад / Вперёд / В конец** и ползунок меняют выбранный шаг.
- **Пуск / пауза** проходит по одному событию каждые полсекунды. Время воспроизведения не равно модельному времени; соседние события могут иметь одинаковый timestamp.
- Выбор строки в **Событиях** или строки на диаграмме переводит на соответствующий шаг.
- **К причине** переходит по зафиксированной причинной ссылке; цепочка ссылок видна в **Причинах**.
- **Следующий тайм-аут** находит следующее истечение таймера. Поиск ищет события, узлы, операции и поля журнала; следующий результат выбирается с переходом через конец списка.
- **Показывать будущие события** рисует последующие строки текущего фрагмента бледным цветом. Расчёт состояния таймеров, ресурсов и контекстов всё равно ограничен выбранным шагом.
- Закрытие окна или смена сессии останавливает воспроизведение.

Диаграмма показывает до 120 событий в одном фрагменте; переход к другому шагу автоматически переключает фрагмент. Его диапазон указан над диаграммой. По вертикали идёт **порядок событий**, не пропорциональная шкала времени. Точное время в миллисекундах указано возле каждой строки. Колонки — участники процедуры. Создание сообщения означает начало его обработки, а не немедленную доставку: отдельно записываются передача по каналу и приём адресатом.

Колесо прокручивает диаграмму, Ctrl+колесо меняет масштаб, кнопки − / + / 1:1 управляют увеличением. Можно прокручивать по горизонтали при большом числе участников. Выбранная строка автоматически попадает в видимую область.

## Содержимое вкладок

**Причины.** Показывает событие, абсолютное время, время от начала процедуры, message/RPC/transfer ID и поля события. Ссылки соединяют фактические операции: установку таймера с его истечением, истечение с повтором, отправку с приёмом, начало CPU/БД с завершением. Поздний ACK или повторный DATA не подменяет причину уже идущей обработки на следующем узле.

**События.** Весь записанный журнал выбранной процедуры. Номера задают порядок при одинаковом времени. Запись может продолжаться после ответа процедуры: поздние ACK/DATA, пользовательские пакеты и истечение TTL контекста ещё используют ресурсы.

**Таймеры.** Таймеры процедуры, вложенных RPC 5G, транспорта, очереди БД, контекстов и пользовательских пакетов. Показаны состояние, срок и оставшееся время относительно выбранного шага. Отмена и истечение различаются. Получение ACK после исчерпания повторов отображается отдельно с признаком того, принял ли его отправитель. Таймер контекста может оставаться действующим после завершения процедуры.

**Время, ms.** По каждому сообщению суммируются записанные ожидания CPU, БД и канала, а также работа CPU/БД до выбранного момента. В деталях отправки DATA есть ожидание допуска транспорта при ограниченном окне; в канальном событии — ожидание сериализации, сама сериализация и распространение. Запланированные будущие границы передачи подписаны отдельно. Незавершённое ожидание/работа учитываются только до выбранного времени. Суммы обращений, переходов и фрагментов нельзя складывать как независимые слагаемые задержки процедуры: часть работы и передач параллельна или относится к повторам.

**В работе.** Активная обработка CPU и БД и их очереди на выбранном шаге. Видны узел, сообщение и прошедшее время. Для отказа фиксируется фактически выполненная часть работы и прерывание очереди.

**Контексты.** Исходное состояние и изменения абонентских и 5G-контекстов, их TTL, удаление, вытеснение и очистка после перезапуска. Общий контекст может изменить другая процедура: её ID записывается, если известен. Такие записи не означают, что выбранная процедура сама выполнила это изменение.

Для **вероятностной БД** отдельной очереди нет: добавленная задержка входит в CPU и явно показана в событии CPU. Для **очередной БД** фиксируются соединение, ожидание, обработка, переполнение, попадание в кэш и тайм-аут.

Маршрут сопровождается режимом выбора, представлением доступности, lookup key, совпавшим правилом, списком разрешённых next hop, рангом и стоимостью выбранных переходов. Это объяснение алгоритма данной модели, а не воспроизведение полного протокола маршрутизации. Для SS7 дополнительно записываются локальный узел GTT, совпавший префикс и результат перевода; для 5G — выбор NF и вложенные RPC.

Причинные ссылки отражают то, что записал движок. Соседство строк по времени не доказывает причинность. Например, истёкший таймер достоверно запускает повтор, но рост общей очереди может зависеть и от других процедур, не попавших в выборку. Глубина очереди показывается фактически наблюдавшаяся; единственный виновник задержки автоматически не назначается.

## Экспорт

**Экспорт таблиц…** сохраняет события, таймеры, времена, ресурсы и контексты через обычное окно оформления в CSV/TSV/JSON/XLSX/HTML/PDF. Снимки состояния соответствуют выбранному шагу; таблица событий содержит весь записанный журнал.

**Диаграмма: фрагмент…** сохраняет текущий фрагмент в PNG, SVG или PDF с текущей темой и настройкой будущих событий. Это не весь журнал из нескольких фрагментов. SVG и PDF векторные; PNG ограничен по числу пикселей. Для полного анализа используйте **Журнал JSON…**: он содержит версию формата, ID прогона, данные сессии и все записанные причинные ссылки. Версия формата — `procedure-journal-v1`; ML-контракт признаков этим расширением не меняется.
