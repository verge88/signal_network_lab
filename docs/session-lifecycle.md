# Жизненный цикл 5G-сессий · 2.13

Движок 2.8.0 различает регистрацию UE и каждую PDU-сессию. Сессия имеет PDU Session ID, владельца — процедуру создания — и отдельные контексты AMF, SMF, UPF и PCF. Один абонент может использовать несколько ID одновременно, в том числе для разных DNN. Освобождение одного ID не удаляет остальные и не отменяет регистрацию.

## Настройка

Откройте поток → **5G · Жизненный цикл**. «Первый PDU Session ID» и «Количество доступных ID на UE» задают последовательный диапазон внутри 1–15. Каждая новая процедура занимает один свободный ID; это не создание всего диапазона за один запрос. Для заполнения нескольких ID нужны повторные обращения того же UE. При занятом диапазоне результат — `pdu_session_in_use`. Другие группы gNB/UE/PLMN имеют собственные диапазоны. Для отдельных DNN одного UE назначайте непересекающиеся диапазоны.

«Сигнальное освобождение через» отсчитывается от получения успешного PDU Accept. Ноль отключает этот таймер, но не TTL контекстов. «Отмена регистрации через» запускает отдельную процедуру для всего UE; ноль оставляет её запуск явному потоку. Оба таймера работают при выключенных пользовательских пакетах. Таймеры за пределами периода эксперимента не запускаются.

В редакторе узла задаётся отдельный лимит **Контекстов PDU-сессий на узел**. Он не заменяет лимит контекстов регистрации. Живые сессии не вытесняются ради новых; нехватка места возвращает `pdu_context_limit`, затем запускается очистка частично созданного состояния. Для PDU-контекстов используется TTL узла; запись продлевает его, чтение — нет.

Операция **5G PDU Session Release** освобождает ID из поля «Первый PDU Session ID». Операция **5G Deregistration** снимает регистрацию и освобождает все живые сессии UE, включая другие DNN. Исходные gNB, PLMN и номер абонента должны совпадать с созданными сессиями. Для первого воспроизводимого опыта задайте один UE, диапазон из двух ID и таймеры освобождения и отмены регистрации. Все потоки начинают создавать нагрузку с начала эксперимента; отдельного расписания запуска потоков пока нет. Новый прогон начинает состояние заново, результаты разных прогонов не продолжают одну сессию.

## Обмен и ошибки

Освобождение проходит через gNB → AMF, Nsmf ReleaseSMContext, PFCP Session Deletion, Npcf SMPolicyDelete и NGAP PDUResourceRelease. Отмена регистрации дополнительно проходит через UDM/UDR и AUSF. Эти модельные сообщения занимают CPU, БД и транспорт как остальная нагрузка. Контекст удаляется на конкретном получателе после успешной обработки; потерянный ответ не восстанавливает уже удалённый контекст.

При частичном завершении недоступный узел сохраняет свой контекст. Состояние сессии становится **Остались ресурсы**, а не «успешно освобождена». Повторная очистка независимо обращается к оставшимся узлам: сбой UPF не мешает освободить достижимые PCF, SMF и AMF. Число повторов и интервал задаются в потоке. После исчерпания бюджета оставшиеся ресурсы видны в отчёте; автоматической бесконечной очистки нет.

Истечение TTL и перезапуск узла останавливают пользовательские пакеты и запускают согласование сохранившихся контекстов. Перенос обслуживающих узлов переносит все PDU ID соответствующей когорты с проверкой вместимости и конфликтов; при уже идущей очистке перенос отклоняется. Поздний ответ старой процедуры не создаёт контекст заново и не удаляет новое поколение того же ID.

После отмены регистрации `initial_registered` не восстанавливает обслуживание. Нужна новая успешная **5G Registration**. Эпоха UE защищает новую регистрацию от запоздалых операций прежней отмены регистрации. Незавершённая отмена отдельно учитывается в отчёте и может оставлять UE заблокированным до завершения моделируемого обмена.

## Просмотр и экспорт

Откройте **Исследование → Жизненный цикл 5G-сессий…** или кнопку **PDU-сессии** в телеметрии. Верхняя таблица показывает владельца, ID, UE, DNN/срез, выбранные узлы, состояние, время и число попыток очистки. Поиск и фильтр состояния работают вместе. Выбор строки ограничивает нижние таблицы переходами этой сессии и её оставшимися контекстами. Двойной щелчок открывает пошаговый разбор исходной процедуры, включая доступные события очистки после ответа.

Столбец «Автоочистка» считает автоматические циклы освобождения и согласования, включая первый. Явная процедура пользователя и отдельные RPC-повторы в это число не входят.

Три таблицы экспортируются с настройкой оформления в CSV, TSV, JSON, XLSX, HTML и PDF. «Отчёт JSON» сохраняет исходный отчёт жизненного цикла, независимо от фильтра. Агрегаты охватывают все сессии; список сессий — равномерная выборка при превышении лимита трасс, список переходов — начало журнала до этого лимита. Усечение явно показано. Подробный пошаговый журнал имеет отдельную выборку и лимит событий; отсутствие журнала не заменяется придуманной диаграммой.

Состояние показано на конец расчёта, включая завершение уже начатых обменов. Если TTL истёк только при итоговой проверке за периодом наблюдения, отчёт помечает сессию как оставшуюся без согласования с причиной `expired_after_observation`; дополнительная очистка за пределами расчёта не выдумывается. Старые сохранённые прогоны не пересчитываются, окно сообщает об отсутствии отчёта.

## Проверка и границы

Автоматические сценарии проверяют два ID одного UE, разные DNN, ограничение вместимости, освобождение без пользовательского трафика, отмену регистрации и повторную регистрацию, TTL, перенос двух сессий, частичный сбой создания, задержанный ответ, недоступный и восстановившийся UPF, повторное использование ID и независимость результата от записи журнала. Нативная проверка охватывает фильтры, переход к процедуре, экспорт и пять тем.

Это поведенческие обмены внутри автономного симулятора. NAS-кодирование, полные автоматы 3GPP, радио, криптография и совместимость с оборудованием не реализованы. Ограниченный бюджет очистки не гарантирует восстановление при произвольной последовательности отказов. Кластеры и репликация состояния — отдельное последующее расширение.
